## 4. Модель данных и функции

**Краткое описание полей задач:** id - уникальный идентификатор задачи, completed - статус задачи, priority - приоритет задачи, title - название или описание задачи

**Почему id не равен индексу:** id не обязан равняться индексу, индекс отвечает за место хранения задачи в массиве задач, id это логический идентификатор конкректной задачи  
**Почему getTaskStats возвращает число, а не строку с процентом:** сводка возвращает необработанное число, так как полное значение может понадобиться в расчетах. это также соответсвует принципу разделения обязанностей. округление может происходить непосредственно перед выводом.  
**Какие объекты копируются при изменении задачи:** при изменении задачи копируются и переносятся в новый массив все обьекты, за исключением изменяемого, он копируется, изменяется и добавляется отдельно.

## 9. Вывод

В сравнении с ПР1, работа проводилась в несокльких файлах с четким разделением обязанностей.
`src/task-service.js` Отвечал за функционал, используемый проверками и основной программой.
`src/main.js` содержал основной сценарий программы.
`src/data.js` содержал общий массив задач и вариантный массив задач, используемый основной программой. (Для проверок он задан повторно, отдельно).
`checks.js` содержал код для автоматической проверки правильной работы функций.
Это соответсвует принципу разделения обязанностей.

Возвращаемые значения используются для обмена информацией между частями программы. `main.js` содержит основной сценарий программы, и получает итоговый возврат функций содержащихся в `task-service.js`. Проверки выводили результаты отдельно, хотя тоже использовали функции из того же файла.
Итоговая неизменность данных проверена выводом массивов в консоль. В коде проверок неизменность проверяется с помощью функций проверки глубокого/поврехностного соответсвия.
Основные допущенные и исправленые ошибки в ходе работы были связаны с валидацией входных данных и созданием нового массива после изменения данных вместо изменения исходного массива.
